# Varmeflyt prototype

Varmeflyt is an interactive, Norwegian-language prototype for heat-pump and HVAC field-service companies. It demonstrates the technician’s daily work surface, order readiness, offline/sync states, and the in-app help assistant described in the frozen product specification.

This repository currently contains a **static phase-0 prototype**, not the production platform. Customer data, completion commands, synchronization, permissions, and assistant responses are simulated in the browser.

## Start locally

Requirements: Node.js 22 or newer.

```bash
npm run dev
```

Open `http://localhost:4173`.

To create the deployable output without starting a server:

```bash
npm run build
```

## Product reference

Read [`docs/design-spec-v1.4.2.md`](docs/design-spec-v1.4.2.md) before making product or UX decisions. Version 1.4.2 is frozen for the phase-0 prototype. [`AGENTS.md`](AGENTS.md) summarizes the repository-specific workflow and guardrails for coding agents.

## What the prototype covers

- Responsive desktop and mobile navigation
- “I dag” schedule with realistic Norwegian demo data
- Order list, filtering, global search, customer and device views
- Completion readiness with a direct link to a missing requirement
- Inline validation and a simulated completion command
- Explicit synchronization and follow-up states
- User-selectable text size
- The three representative help-assistant interactions in the specification

## Demo boundary

Every order carries its own demo record, so the order list, the drawer, the
readiness summary and the assistant always agree about the same order. Controls
that are outside the prototype say so when pressed instead of doing nothing —
useful in usability sessions, where a silent control reads as a product defect.

Readiness is still staged data, not a rule engine: each order declares its own
outstanding items, and the drawer derives progress, the completion state and the
assistant's answer from that one list. The real requirement engine (§2.9 of the
specification) is phase-0 work and does not exist here.

## Deployment metadata

`.openai/hosting.json` links this checkout to the existing private OpenAI Sites project and declares `dist/` as its static output directory. It contains no chat history, API keys, or deployment credentials. Keep it committed so Sites-aware tooling updates the same project; other development tools may safely ignore it.

The current private prototype is available at [varmeflyt-prototype.avalia-chatp-5475.chatgpt.site](https://varmeflyt-prototype.avalia-chatp-5475.chatgpt.site).

## Contributing

1. Edit files in `src/`, not `dist/`.
2. Keep visible interface text in Norwegian Bokmål unless localization work is explicitly in scope.
3. Run `npm run check` before committing.
4. Keep the static prototype clearly separated from future production architecture.

Do not commit credentials, customer data, local environment files, or generated deployment archives.
